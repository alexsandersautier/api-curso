# Products and Product Items Implementation Plan

> **For agentic workers:** Execute tasks inline. User runs database and test commands manually.

**Goal:** Add product catalog and purchasable product item APIs.

**Architecture:** A `products` app owns `Product` and `ProductItem`. Separate DRF viewsets expose `/products/` and `/product-items/`, with public active reads and admin-only writes. Django migrations manage both tables.

**Tech Stack:** Python 3.13, Django 5.2, Django REST Framework, PostgreSQL, drf-spectacular, Ruff.

**Spec:** `docs/superpowers/specs/2026-09-26-products-design.md`

## Global Constraints

- Use UUID primary keys for both entities.
- Use `DecimalField` for item prices and reject negative prices.
- Use `PROTECT` for category and product foreign keys.
- Public reads include active products and active items whose parent product is active.
- Admin writes require `role = admin`; do not expose `PUT` or `DELETE`.
- Do not add inventory, cart, or order behavior in this phase.
- Do not run tests, migrations, or servers automatically.

### Task 1: Add product catalog models and migration

**Files:**
- Create: `products/__init__.py`, `products/apps.py`, `products/models.py`
- Create: `products/migrations/__init__.py`, `products/migrations/0001_initial.py`
- Modify: `core/settings.py`

**Interfaces:**
- `Product`: UUID, protected category FK, name, description, `is_active`, timestamps.
- `ProductItem`: UUID, protected product FK, unique SKU, name, non-negative decimal price, `is_active`, timestamps.

- [ ] Add model definitions and category migration dependency.
- [ ] Add database check constraint `product_item_price_non_negative` and field minimum validator.
- [ ] Register `products` in `INSTALLED_APPS`.
- [ ] Review migration operations against both models.

### Task 2: Add admin and serializers

**Files:**
- Create: `products/admin.py`, `products/serializers.py`

**Interfaces:**
- `ProductSerializer`: read-only output with category UUID.
- `ProductWriteSerializer`: category, name, description, and active status.
- `ProductItemSerializer`: read-only output with product UUID and decimal price.
- `ProductItemWriteSerializer`: product, SKU, name, price, and active status.

- [ ] Register searchable, filterable admin models.
- [ ] Add serializers with explicit fields and non-negative decimal input validation.

### Task 3: Add API viewsets and routes

**Files:**
- Create: `products/views.py`, `products/urls.py`
- Modify: `core/urls.py`

**Interfaces:**
- `ProductViewSet`: list/retrieve public active rows; admin sees all; admin create/PATCH.
- `ProductItemViewSet`: same access, with public queryset restricted to active item and active parent product.
- Route collection paths `/api/v1/products/` and `/api/v1/product-items/`.

- [ ] Restrict HTTP methods to GET, POST, and PATCH (plus HEAD/OPTIONS).
- [ ] Use `select_related` for category and product relations.
- [ ] Tag OpenAPI operations as `Products` and `Product items` with read/write serializers.
- [ ] Return standard DRF validation errors for bad relations, duplicate SKU, or invalid price.
